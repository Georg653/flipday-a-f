# Обновление фронтенда: телефон и JSON

Бэкенд и Docker для этого обновления менять не нужно. Архив содержит только frontend.

## Обновить и запустить (Windows PowerShell)

1. Остановите старый фронт: Ctrl+C в его терминале.
2. Сохраните свой frontend/.env.local отдельно. Распакуйте новую папку frontend и верните туда сохранённый .env.local. Архив намеренно не содержит персональных настроек подключения.
3. В терминале новой папки frontend:

```powershell
npm ci
npm run check
npm run dev
```

4. Откройте http://127.0.0.1:5174 и обновите Ctrl+Shift+R. Терминал с npm run dev оставьте работающим.

Если запускаете впервые, создайте .env.local из .env.local.example. Для локального API:

```dotenv
VITE_API_BASE_URL=http://localhost:8003/v1/admin/
VITE_MINIO_URL=http://localhost:9000
```

Бэкенд должен быть запущен, вход — существующим администратором. После смены адресов перезапустите npm run dev.

## Предпросмотр

Новости, точки, страницы обучения и истории используют рамку телефона 320 × 660 CSS-пикселей. Размер одинаков в таблице и редакторе, независимо от длины материала. Длинные страницы прокручиваются внутри. Главное изображение уменьшено до 145 пикселей по высоте, отдельное изображение — до 180. Сам интерфейс приложения остаётся светлым.

## Заполнить одну форму

Нажмите обычную кнопку добавления или редактирования. Откройте «Заполнить из JSON»: загрузите файл или вставьте текст, нажмите «Заполнить форму». Сначала просмотрите заполненные поля, затем нажмите обычное сохранение. На этапе заполнения запрос создания не отправляется.

«Копировать шаблон» даёт JSON именно текущего раздела. Готовые примеры находятся в examples/form-*.json. Можно передать только нужные поля; остальные значения формы сохранятся. Массивы контента и слайдов при передаче заменяются целиком. Для родителя в отдельной форме используются числовые ID; для новой подтемы/страницы можно оставить выбранного родителя, не передавая его ID.

## Заполнить несколько разделов

Слева под «Страницы тем» откройте «Импорт JSON». Загрузите examples/import-all.json либо скопируйте шаблон из интерфейса. Формат:

```json
{"version":1,"records":[
  {"type":"topics","key":"city","data":{"name":"Изучаем город"}},
  {"type":"subtopics","key":"start","data":{"name":"Начало","topic_id":"city"}},
  {"type":"pages","key":"lesson","data":{"page_number":1,"subtopic_id":"start","content":[{"type":"text","content":"Первый урок"}]}}
]}
```

Поддерживаются news, stories, points, routes, categories, topics, subtopics, pages, achievements. Предложения пользователей API создавать не позволяет.

Связи: topic_id → ключ темы; subtopic_id → ключ подтемы; route_category_id → ключ категории; points → массив ключей точек. Числовые ID относятся к существующим данным. Порядок в файле произвольный: родители создаются раньше зависимых записей.

Нажмите «Проверить JSON», посмотрите список, затем «Создать … записей». Проверка не меняет базу. Лимит: 5 МБ / 2000 записей. Ошибки полей и отсутствующие ссылки показываются до отправки; существование числовых ID проверяет API при создании.

Импорт создаёт новые записи, не обновляет существующие. Успешные записи сохраняются сразу: это не единая транзакция. Если API отказал, результат виден напротив записи; кнопка продолжения повторит неудавшиеся и зависимые записи, пропуская успешные в текущем запуске. «Остановить» действует после текущего запроса. Не перезагружайте страницу во время импорта: после перезагрузки история успешных ID теряется, повторная загрузка того же файла может создать дубликаты. При обрыве связи проверьте базу: сервер мог успеть создать запись до потери ответа.

JSON не упаковывает бинарные изображения/видео. Используйте реальные доступные http/https URL или загрузите файлы вручную в форме. URL example.com — заглушки, их нужно заменить. Для stories в общем импорте обязательны preview_url и content_items; в форме изображение превью можно выбрать отдельно. Даты expires_at: ISO 8601 с часовым поясом (например 2027-01-02T15:00:00+03:00) или null; даты без пояса трактуются как UTC.

## Что проверено

ESLint, TypeScript, production-сборка и 45 frontend-тестов. Дополнительно 7 HTTP-тестов с настоящими frontend-сервисами и отдельным тестовым API, включая создание всех восьми связанных записей из общего шаблона. Пользовательскую базу тесты не меняли. Визуальную проверку в браузере этого окружения выполнить не удалось; проверьте превью и импорт на своём стенде.
