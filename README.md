# Frontend — отдельный проект FlipDay Admin

React + TypeScript + Vite. Нужен Node.js 24.15 или новее из ветки 24 (проверено на 24.22.1). Проект содержит package-lock.json: устанавливай зависимости через npm ci.

## 1. Распаковать и настроить

Открой терминал именно в папке frontend. Для локального бэкенда из соседней папки:

PowerShell:

```powershell
if (!(Test-Path .env.local)) { Copy-Item .env.local.example .env.local }
```

macOS/Linux:

```bash
test -f .env.local || cp .env.local.example .env.local
```

В файле должны быть:

```dotenv
VITE_API_BASE_URL=http://localhost:8003/v1/admin/
VITE_MINIO_URL=http://localhost:9000
```

Для проверки существующего сервера можно сразу указать его адреса вместо localhost. API_BASE_URL — полный префикс админского API, желательно со слешем на конце. VITE_MINIO_URL — базовый адрес перед `/media/`: например `https://домен/api/download`, а не полный URL одного изображения.

## 2. Установка и все проверки

```bash
node --version
npm ci
npm run check
```

Команда check последовательно выполняет ESLint, 45 тестов и production-сборку с проверкой TypeScript. Если любая проверка упала, команда останавливается с ошибкой. Отдельно доступны `npm run lint`, `npm test`, `npm run build`.

Тесты работают с подменой API и не требуют поднятого бэкенда. Для проверки реального сохранения нужен работающий API и администратор.

## 3. Открыть в браузере

```bash
npm run dev
```

Открой адрес из терминала (обычно http://127.0.0.1:5174/login). Войди администратором. Для локального стенда его создают командой из инструкции backend. Регистрация нового пользователя сама по себе не даёт административных прав.

После смены .env.local перезапусти npm run dev. Остановить сервер — Ctrl+C.

Проверь интерфейс по `MANUAL_CHECKLIST.md` из общего архива. Если тебе передали только эту папку: создай запись в каждом разделе, перезагрузи страницу, отредактируй её, проверь сохранённые файлы и удали. Отдельно проверь переход на вторую страницу таблиц и обратно, поиск и сообщения ошибок.

## 4. Сборка для хостинга

1. Удали локальный `.env.local` из папки сборки либо замени в нём адреса на реальные: Vite читает этот файл и при production-сборке, он может перекрыть .env.production.
2. Скопируй `.env.production.example` в `.env.production` и впиши реальные адреса API и медиа, согласованные с разработчиком бэкенда.
3. Выполни:

```bash
npm ci
npm run check
```

4. Проверь готовую сборку:

```bash
npm run preview -- --host 127.0.0.1
```

5. Открой адрес из терминала, обычно http://localhost:4173/login. Затем загрузи содержимое dist на хостинг фронта. Исходники backend и SQL на этот хостинг не загружаются.
6. Веб-сервер должен отдавать index.html для SPA-маршрутов `/login`, `/admin/news` и остальных. Пример nginx-конфига находится в `nginx.example.conf`.

Переменные VITE_* встраиваются в сборку. Изменение .env после сборки само по себе не меняет адрес API в уже созданном dist — нужно собрать заново.

## 5. Как разбирать ошибку

Открой инструменты разработчика браузера → Network. Повтори действие и посмотри неудачный запрос: адрес, HTTP-статус и Response.

- ERR_CONNECTION_REFUSED / Failed to fetch — API не запущен, неверный адрес либо сеть/CORS.
- 404 — проверь префикс `/v1/admin/` для локального запуска или `/api/v1/admin/` для сервера с соответствующим прокси.
- 401 — войди заново. 403 — нужны права администратора на бэке.
- 422 — проверь detail ответа: сервер отклонил поля формы.
- 500 — нужны логи бэкенда; одним обновлением страницы такую ошибку не исправить.
- Данные есть, картинки не открываются — проверь VITE_MINIO_URL, доступность бакета и прямой URL картинки в Network.
- После обновления страницы админки сервер возвращает 404 — настрой SPA fallback на index.html.

В этой версии нет кнопки импорта JSON. Для заполнения тестовыми записями и проверки настоящего API используется скрипт `backend/scripts/smoke_api.py`; он создаёт примеры с файлами и позволяет оставить их через `--keep`.
